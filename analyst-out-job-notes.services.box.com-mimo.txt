[CONFIRMED] upload.box.com/api/2.0/* — CORS Origin Reflection with Credentials on POST Preflight (Blind CSRF File Upload)

class: MISCONFIG
asset: upload.box.com/api/2.0/{files/content, files/upload_session, collaborations, tasks, folders, comments, groups, events, shared_items}
confidence: 95
reasoning: |
  OPTIONS preflight on ALL POST collection endpoints reflects ANY Origin (evil.example.com, null, box.com.evil.com, app.box.com) in access-control-allow-origin with access-control-allow-credentials: true. Allows POST with Authorization and Content-Type headers. Live endpoint confirmed (POST returns 400/401, not 404). Null Origin widens attack surface to sandboxed iframes. HOWEVER: POST response itself has NO CORS headers — attacker JS cannot read the response body (blind CSRF only). Server uses Bearer token auth exclusively — session cookies from app.box.com are NOT accepted by upload.box.com (tested with box_session_token cookie → 401 "access token was not found"). Format-before-auth ordering: content-type → auth → file-content.
verify_steps: |
  1. OPTIONS https://upload.box.com/api/2.0/files/content with Origin: null → 200, ACAO: null, ACAI: true ✓
  2. OPTIONS with Origin: evil.example.com → ACAO: https://evil.example.com, ACAI: true ✓
  3. OPTIONS with Origin: box.com.evil.com → ACAO: https://box.com.evil.com, ACAI: true ✓ (subdomain trick accepted)
  4. OPTIONS with Origin: app.box.com → ACAO: https://app.box.com, ACAI: true ✓ (self-origin accepted, enables same-site CSRF)
  5. POST with multipart + invalid Bearer token → 401 (no CORS headers on response) ✓
  6. POST with multipart + fake session cookie → 401 "access token was not found" (cookie auth not supported) ✓
  7. POST with JSON Content-Type → 415 (content-type gate) ✓
  8. POST with multipart + no file → 400 "API upload did not contain a file part" ✓
impact: |
  An attacker page (evil.com) or sandboxed iframe (file://, data:) can force a logged-in Box user to upload arbitrary files to their account via blind CSRF. LIMITATIONS: (1) Attacker cannot read the response — no data exfiltration. (2) Server requires a valid Bearer token — session cookies are NOT accepted, so the attacker must first exfiltrate the victim's API token (e.g., via XSS on app.box.com). (3) Can only force file uploads, not read file contents. Severity: LOW-MEDIUM — CORS misconfiguration amplifies token theft, but cannot be exploited standalone without a prior token theft.
testability: AUTH_HELPED
