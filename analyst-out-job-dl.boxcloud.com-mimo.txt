**Key Finding: `redirect_uri` parameter reflection in embed prefetchedData**

The `/embed/shared/{token}` and `/embed/file/{id}` endpoints both reflect arbitrary query parameters (including `redirect_uri`) into the `Box.prefetchedData` JSON. Specifically, `redirect_uri=https://evil.com` gets reflected into:
- `url` field → used as iframe `src` after challenge completion
- `displayedURL` field → used as initial iframe `src` 
- `originalURL` field → used in `window.location.assign(o)` during MS Teams auth flow

The `redirectParentIframe` action also allows the child iframe to trigger `window.location.href = n.url` navigation on the parent.

However, the server-side `/shared/{token}` returns 404 for invalid tokens, and path traversal returns 403. The question is whether a *valid* shared link token combined with `redirect_uri` would cause the server to redirect to the attacker-controlled URL.
